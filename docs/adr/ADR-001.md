# ADR-001: Elección de Ionic Angular (Standalone) y arquitectura por capas como estándar frontend

- **Estado:** Aprobado
- **Fecha:** 2026-11-21
- **Autor(es) y equipo:** Vargas Chávez Michael Jordan (Proponente) — Equipo Grupo 5: Díaz Bedón Daniel Andrés, Lucero San Lucas Jimy Sullivan, Vargas Chávez Michael Jordan
- **Requisitos relacionados:** Punto 1 (Contexto y objetivo: control de escrutinio electoral con tres roles y compilación móvil), R1 (Datos iniciales), R2 (Validación de cédula ecuatoriana), R4 (Coordinador provincial), R5 (Coordinador de recinto), R6 (Veedor y cuadre de actas), R9 (Arquitectura por capas y UX).

## Contexto

Una organización política de Ecuador requiere desarrollar una aplicación móvil compilable a Android (APK) para gestionar, registrar y supervisar el escrutinio electoral desde las Juntas Receptoras del Voto (JRV) hasta la consolidación provincial. El sistema contempla tres roles con niveles de acceso diferenciados (Coordinador Provincial, Coordinador de Recinto y Veedor de Mesa). Dado que los tres integrantes deben partir de una única línea base antes de desarrollar sus entregas individuales (fecha límite: miércoles 25 de noviembre de 2026), se requiere un framework soportado por Capacitor que separe estrictamente la presentación, la lógica de negocio y el acceso a datos (`src/app/{core, shared, features}`), proteja rutas por rol y facilite validaciones complejas.

## Alternativas consideradas

| Alternativa | Ventajas para este caso | Desventajas / riesgos |
| :--- | :--- | :--- |
| **Opción A: Ionic Angular (Standalone Components, TypeScript) + Arquitectura en 3 capas (`core`/`shared`/`features`)** | Inyección de dependencias nativa (`inject()`); Guards funcionales de ruta (`authGuard`, `roleGuard`, `firstLoginGuard`) e interceptores; `ReactiveFormsModule` con validadores puros para cédula ecuatoriana (R2) y cuadre matemático de actas (R6); estructura modular uniforme que evita divergencias entre los repositorios del grupo. | Curva de aprendizaje inicial más estricta en TypeScript y programación reactiva; requiere configurar carga perezosa (*lazy loading*) por ruta y rol para optimizar el paquete inicial. |
| **Opción B: Ionic React (React 18 + TypeScript + React Router)** | Sintaxis JSX directa, menor tamaño de *bundle* inicial y ecosistema amplio de componentes comunitarios. | No incluye inyección de dependencias, sistema de formularios validados ni Guards declarativos de fábrica; obliga a combinar librerías externas (Zustand/Redux, React Hook Form, Zod), elevando el riesgo de arquitecturas dispares entre integrantes. |
| **Opción C: Desarrollo nativo Android (Kotlin / Jetpack Compose)** | Acceso directo al hardware de cámara y GPS sin capa puente. | Descartada por incumplir la condición técnica obligatoria de la evaluación (únicamente se admiten Ionic Angular standalone o Ionic React con Capacitor). |

## Decisión

Se elige Ionic Angular con arquitectura Standalone (sin `NgModules` heredados), TypeScript en modo estricto, carga perezosa (`loadComponent` / `loadChildren`) separada por rol (`auth`, `provincial`, `recinto`, `veedor`) y organización en tres capas por dominio (`core/models`, `core/validators`, `core/services`, `shared/`, `features/`), prohibiendo llamadas directas a backend desde las vistas.

## Consecuencias

- **Beneficios:** Coherencia arquitectónica entre los tres integrantes, reutilización de validadores puros de cédula y cuadre de votos, y protección declarativa de rutas mediante Guards.
- **Obligaciones:** Mantener sincronizadas las interfaces en `core/models/` con los documentos de Firebase y Supabase.
- **Limitaciones y riesgo:** Un uso excesivo de suscripciones RxJS sin limpieza o gráficos pesados en el dashboard provincial (R4) puede degradar el rendimiento en dispositivos Android de gama baja; se mitiga aplicando *lazy loading* y gestión reactiva eficiente.

## Verificación

Revisar `package.json` confirmando `@ionic/angular` y `@capacitor/core`; inspeccionar `src/app/app.routes.ts` verificando `canActivate: [authGuard, roleGuard]` en cada módulo de rol; ejecutar pruebas unitarias de los validadores de cédula ecuatoriana y cuadre de actas, y comprobar compilación limpia con `ionic build`.

## Uso de IA

- **Herramienta:** Gemini.
- **Consulta:** *"Comparativa técnica entre Ionic Angular Standalone e Ionic React y arquitectura en capas para un sistema electoral multi-rol"*.
- **Respuesta sugerida:** Adoptar Ionic Angular Standalone con estructura `core`/`shared`/`features` por sus Guards nativos, Reactive Forms e inyección de dependencias.
- **Aceptación y verificación humana:** Aceptado tras contrastar con los requisitos Punto 1 y R2–R9 y validar el esquema de rutas protegidas.
